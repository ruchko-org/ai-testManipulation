# Промпт: создание образовательного квиза на Flask

Создай Flask-приложение — образовательный квиз для старшеклассников на тему «<ТЕМА>».

## 1. Файл `questions.py` — банк из 200 вопросов

Каждый вопрос — словарь:

```python
{
    "id": 1,                          # 1..200, уникальный
    "category": "<Тема/техника>",     # например, «Фишинг», «Социальная инженерия»
    "question": "Текст вопроса или практический кейс?",
    "options": ["Вариант 1", "Вариант 2", "Вариант 3", "Вариант 4"],
    "correct": 2,                     # индекс правильного варианта (0..3)
    "explanation": "Общее объяснение в 2-3 предложения.",
    "option_explanations": [
        "Неверно. Почему вариант 0 неправильный. Например: <пример>.",
        "Неверно. Почему вариант 1 неправильный. Например: <пример>.",
        "Верно. Почему вариант 2 правильный. Например: <пример>.",
        "Неверно. Почему вариант 3 неправильный. Например: <пример>."
    ]
}
```

## 2. Правила для `option_explanations`

- Ровно **4 строки** — по одной на каждый вариант.
- Ровно **одна** строка начинается с «Верно.» — она соответствует `correct`.
- Остальные **3** начинаются с «Неверно.».
- Каждая строка: маркер + объяснение почему + **конкретный пример**.
- Индекс «Верно.» ДОЛЖЕН совпадать с полем `correct`.

## 3. Распределение по категориям

- 200 вопросов распределить по **12–20 категориям** равномерно (~10–15 на тему).
- Категории должны покрывать тему целиком, без дублей по смыслу.

## 4. Формат генерации

- Генерировать **чанками по 20–30 вопросов** — так не превышается лимит вывода.
- После каждого чанка — валидация.
- Не допускать дубликатов формулировок вопросов.

## 5. Обязательная валидация после генерации

```python
# Проверить:
# - 200 записей, id 1..200 без пропусков
# - у каждого ровно 4 варианта и 4 объяснения
# - ровно одно «Верно.» на вопрос
# - индекс «Верно.» == correct
```

## 6. Flask-приложение `app.py`

- главная страница с описанием и кнопкой «Начать»;
- страница вопроса: текст, 4 кнопки, прогресс;
- страница объяснения после ответа: показывает `explanation` и разбор всех вариантов из `option_explanations`;
- страница результата с процентом и разбором ошибок;
- `SESSION_SIZE` — сколько вопросов задаётся за прохождение (по умолчанию 30);
- случайная выборка вопросов из банка.

## 7. Структура проекта

- `templates/` — `base.html`, `index.html`, `question.html`, `feedback.html`, `result.html`, `error.html`
- `static/style.css` — чистое читаемое оформление
- `requirements.txt` — flask
- `README.md` — описание, формат вопроса, инструкция запуска

## 8. Типичные ловушки (проверять особо)

- **Смещение индекса `correct`** — модель часто ставит правильный ответ первым или последним. Требуется равномерное распределение индексов 0–3.
- **Дубликаты вопросов** — при генерации большими партиями появляются повторы. Проверять уникальность формулировок.
- **Слишком общие объяснения** — без требования «приведи конкретный пример» объяснения получаются водянистыми.
- **Несовпадение «Верно.» и `correct`** — самая частая ошибка при ручной правке. Всегда включать автовалидацию.
